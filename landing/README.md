# Eddy landing page and docs

The public site at <https://idestis.github.io/eddy/>. Vite, React 19, TypeScript 5.9, Tailwind CSS v4 and TanStack Router (file-based routes), managed with pnpm and linted with Biome. The build output is fully static: every route is prerendered to its own `index.html` with real content (for search engines and readers without JS), then hydrated in the browser.

## Develop

```sh
cd landing
pnpm install
pnpm dev            # http://localhost:5174/eddy/
pnpm build          # typecheck, client build, SSR build, prerender into dist/
pnpm preview        # serves dist/ at http://localhost:4174/eddy/
pnpm lint           # Biome (pnpm format to fix formatting)
pnpm typecheck
pnpm check:links    # runs ../hack/check-links.py against dist/
```

## Base path and domain

The site is served from `/eddy/` (GitHub project page). Two environment variables, read at build time, control the URL layout:

| Variable | Default | Effect |
|---|---|---|
| `LANDING_BASE` | `/eddy/` | Path prefix for every link, asset, route, `sitemap.xml` and `robots.txt` |
| `LANDING_SITE` | `https://idestis.github.io` | Origin used in canonical, Open Graph and sitemap URLs |

Moving to a custom domain at the root is `LANDING_BASE=/ LANDING_SITE=https://example.com pnpm build` (set them in `.github/workflows/pages.yml`).

## How prerendering works

`pnpm build` runs the normal client build, then a Vite SSR build of `src/entry-server.tsx`, then `scripts/prerender.mjs`. The script renders each route with TanStack Router's memory history and `renderToString`, and writes the HTML into the client build's `index.html` template (`<!--app-head-->` and `<!--app-html-->` placeholders). It also writes `404.html` (for GitHub Pages), `sitemap.xml` and `robots.txt`, all generated from the route tree. In the browser, `src/main.tsx` loads the route and calls `hydrateRoot`. The route list comes from `src/routes/`, so a new file there is prerendered and added to the sitemap automatically.

## Layout

- `src/routes/`: pages. `index.tsx` is the landing page; `docs.tsx` is the docs layout and `docs/*.tsx` are the docs pages (add new pages to `src/lib/docs.ts` for the sidebar and pager). `routeTree.gen.ts` is generated by the router plugin and committed.
- `src/components/`: header, footer, code block with Copy button, keymap, cluster list, architecture diagram (a wide and a stacked SVG), hero UI illustration.
- `src/lib/head.ts`: per-route `<title>`, description, canonical, Open Graph and Twitter tags, rendered into the prerendered HTML and kept in sync on client navigation.
- `src/styles/theme.css`: every colour on the site, once, as `light-dark(<light>, <dark>)` tokens in a Tailwind `@theme` block. Edit this one file to re-theme.
- `public/assets/`: favicon, social card (`og.svg`, `og.png`; regenerate the PNG if you change the copy) and self-hosted Geist and Geist Mono (`fonts/`, SIL OFL 1.1, `OFL.txt`). The site makes no third-party requests.
- `scripts/`: `prerender.mjs` and `check-links.mjs`.

## Deploy

`.github/workflows/pages.yml` installs with `pnpm install --frozen-lockfile`, runs `pnpm build` and uploads `landing/dist` to GitHub Pages. The `landing` job in `.github/workflows/ci.yml` runs lint, typecheck, build and the link check on every change under `landing/`.
